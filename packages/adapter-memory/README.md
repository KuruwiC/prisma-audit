# @kuruwic/audit-adapter-memory

A private, in-memory audit adapter built only on the public API of `@kuruwic/db-audit-core`. It is the smallest complete adapter: every `create`, `update` and `delete` goes through `auditGate`, then `policy`, `planFor` and `dispatch`, with a record build of `resolve` and `compose`, its own `WriteExecutor`, and its store and transactions as the transaction runtime. The [core README](../db-audit-core/README.md#reference-adapter) walks through that sequence.

`createMemoryAuditAdapter(options)` takes `schema`, `entities`, `contextProvider` and optionally `requireContext`, `write.mode`, `diffExcludeFields`, `redactFields`, `serializers`, `actorContext` and `observer`. It creates its own store, exposed as the adapter's `store`: tables are maps keyed by model and serialized primary key, and audit records are appended to an in-memory list.

- **Coverage**: a write is audited when its model is in `entities` and an audit context is set. Without a context it runs unaudited, unless `requireContext` (a value, or a function of the model name; default `false`) holds for its model, which rejects it with `AuditContextMissingError` before it is applied. A write of a model not in `entities` never calls the write policy or the actor enricher.
- **Transactions** are copy-on-write overlays of the store. A transaction opened inside another nests in it and is discarded when the outer one rolls back.
- **Write modes**: `write.mode` (`'atomic'`, the default, `'awaited'` or `'deferred'`) applies to models whose entity sets no `writeMode`. An atomic write runs in the active transaction or opens one. Inside a transaction every mode writes the audit rows into the transaction's buffer, so they commit and roll back with the data. Outside one, `awaited` writes them after the write is applied, and `deferred` starts a detached write that `flush()` waits for.
- **Reads**: id resolvers and enrichers read through the handle of the transaction they run in. The store holds every row's before state, so the adapter has no `fetchBefore` option and ignores an entity's.
- **Outcomes**: every write of a model in `entities` has an outcome, passed to `observer` once the outermost transaction it ran in ends, or, outside any, once the write returns or throws (for a `deferred` write, once its detached audit write finishes). Before forwarding it, the adapter appends failed audit writes to `writeFailures` (`log-write`) and resolver failures to `resolverFailures` (`id-resolver-call`). Because the adapter always observes outcomes itself, the core never logs lost records to the console.
- **Failures**: a failed audit write in a transaction rejects the write and rolls the transaction back, whatever the mode; an audit write outside a transaction never fails the write. A failure of the entity's id resolver leaves the row without its records, and a `to()` resolver's without that root's record: an atomic write fails with `AuditIncompleteError` and rolls back, an awaited or deferred one succeeds with an `incomplete` outcome. A record build that fails after a write outside a transaction drops its records, with an `incomplete` outcome and a `diff-generation` failure.

The package is not published. `pnpm --filter @kuruwic/audit-adapter-memory test` runs its spec.
